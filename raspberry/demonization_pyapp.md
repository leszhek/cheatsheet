## Демонизация python-приложения (да - любого приложения)
[Вернуться](./)

Демонизация приложения означает запуск его как демона, то есть в фоновом режиме без привязки к конкретной сессии пользователя. Это часто используется для серверных приложений, которые должны работать непрерывно, даже если никто не вошел в систему.

Самое простое решение - сделать это через systemd конфигурационный файл.

Создайте новый файл с расширением .service в каталоге /etc/systemd/system/. Например, вы можете назвать его my_app.service.

Откройте файл my_app.service в текстовом редакторе и добавьте следующее содержимое:
```
[Unit]
Description=My Python App
After=network.target

[Service]
User=my_user
Group=my_group
WorkingDirectory=/path/to/your/app
Environment="MY_VARIABLE=my_value"
Environment="MY_VARIABLE2=my_value2"
ExecStart=/usr/bin/python3 /path/to/your/app/my_app.py
Restart=always

[Install]
WantedBy=multi-user.target
```

Объяснение каждого раздела:

- **Unit**: Этот раздел содержит метаданные о службе, такие как ее описание и зависимости.
    - *After*: определяет после какого демона будет запущен наш
- **Service**: Этот раздел определяет параметры службы, такие как пользователь и группа, рабочий каталог, переменные окружения, команда запуска и политика перезапуска (тут, думаю, расшифровка не требуется)
- **Install**: Этот раздел определяет, как служба будет установлена и активирована в системе. Определяется одним из двух параметров *WantedBy* и *Also*
    - *WantedBy* определяет цель (target), в рамках которой данная служба должна быть автоматически запущена при активации системы. Это может быть, например, цель multi-user.target, которая обозначает многопользовательский режим системы. Когда цель multi-user.target активируется при загрузке системы, systemd будет автоматически запускать все службы, указанные в разделе [Install] с директивой WantedBy=multi-user.target.
    - *Also* позволяет указать дополнительные цели, в рамках которых служба также должна быть активирована. Это может быть полезно, если вы хотите, чтобы ваша служба запускалась при активации нескольких различных целей.
